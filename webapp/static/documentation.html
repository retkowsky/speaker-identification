Voice identification, step by step

A user guide to recording, comparing, and exploring voice embeddings with Qdrant and Azure AI Search.

1. Quick start

  1. Open the running app at http://127.0.0.1:8765/. Dismiss the welcome screen with Get started or Escape.
  2. Choose Qdrant / Local and wait for the connection/model status to be ready. First startup takes longer while reference embeddings are prepared.
  3. Open Test audio, select one of the 41 held-out test clips, and load it. Listen to the playback if desired.
  4. Select Identify speaker. Read the accepted match or unknown result, ranked similarities, and Match spotlight.
  5. Try a different clip or record your own voice. Use Clear to remove audio and results without deleting speakers.
This is a speaker-similarity demo, not identity verification or authentication. A high similarity score is not a probability of identity.

2. Audio input

Microphone

Use Edge or Chrome on localhost. Select Allow / refresh microphones, grant access, and choose the input device. This permission step does not record audio. Record one speaker for 2 to 30 seconds, stop, review playback, and identify.

Use a quiet environment and a natural speaking voice. The device choice lasts for this page session and cannot change while recording. If the device disconnects, select an available input and retry.

Upload WAV

Browse or drag a single WAV onto the upload area. Accepted audio is 2-30 seconds, mono or stereo, 8-192 kHz, and no larger than 20 MB. The server converts it to mono at 16 kHz. Silence, malformed audio, and nonfinite samples are rejected; heavy clipping generates a warning.

Test audio

The 41 bundled _segment_2.wav clips are held out from the initial reference library. The expected speaker is displayed so you can compare the result with the label. These clips are not automatically enrolled.

The waveform, microphone orb, level meter, and spectrum show actual audio activity, not recognition confidence or an audio-quality score.

3. Understanding results

Open the Match criteria sliders icon in the top bar to adjust the minimum similarity and candidate gap. The panel closes on an outside click or Escape without losing edits. Escape returns focus to the icon; changes apply to the next analysis. Invalid values reopen the panel for correction.

ECAPA-TDNN computes a normalized 192-dimensional embedding locally. The selected database compares it with reference embeddings using cosine similarity. Recognition uses the full vectors, never the distance between dots on the plot.

  • Minimum similarity: default 0.5. The best candidate must meet this threshold.
  • Minimum separation: default 0.05 between the two best different speakers. A close runner-up can cause rejection.
  • Unknown speaker: the strongest candidate is below the threshold or the leading speakers are too similar. This is not proof the speaker is absent.
  • Top N: default 5. Reducing it trims the list immediately. Increasing it uses cached matches where possible, or reruns the current audio when committed. Update results explicitly reruns recognition. Top N = 1 still checks the runner-up for ambiguity.

Bars show similarity on a 0-1 scale, not percentages of certainty. Negative cosine scores remain signed and have empty bars. Values strictly below the applied threshold are red; the bar marker shows that threshold. Changes to criteria apply to the next analysis. Analysis time excludes browser/network time.

The default criteria are not calibrated accuracy guarantees. Test on representative, consented recordings before drawing conclusions about recognition performance.

4. Match spotlight

Available after identification with both Qdrant and Azure AI Search. The badge indicates LOCAL / PCA or AZURE / PCA. This is a PCA projection, not UMAP or t-SNE.

  • Green dot: the accepted speaker's highest-cosine reference sample. At most one reference is green.
  • Red dots: all other references, including any other samples belonging to the matched speaker. Rejected results have no green dot.
  • Neutral diamond: your query recording.
  • Candidate links and labels: follow full-vector cosine matches, not projected distance. Hover, focus, or select a sample to inspect it.

5. Speaker library and enrollment

  1. Select the backend that should store the new speaker.
  2. Record or upload clear speech, then select Enroll this voice.
  3. Enter a unique name and confirm permission to store the voice embedding.
  4. Test using a different recording of the same person.

The Speaker library lets you search names, play bundled reference audio, load references as test samples, and delete your own enrollments. Bundled speakers are read-only. Custom enrollment stores the name and embedding, not the recording, so custom voices have no reference playback.

Qdrant and Azure libraries are separate. Enrolling or deleting in one does not copy or remove data in the other. Matching a stored reference to itself checks the pipeline, not real-world recognition accuracy.

6. Azure AI Search

Use an existing Azure AI Search service with vector-search support and a dedicated app-managed index. The app creates an index when authorized, not an Azure service.

  1. Choose Azure AI Search / Cloud. Enter the HTTPS service endpoint and dedicated index name, then Save settings.
  2. Configure authentication on the server. Prefer Microsoft Entra ID via DefaultAzureCredential (for example, az login for development). Index management needs Search Service Contributor; querying/writing documents needs Search Index Data Contributor. Role-based data access must be enabled on the service.
  3. Alternatively, configure AZURE_SEARCH_API_KEY with an admin key and the matching AZURE_SEARCH_ENDPOINT in the server's .env. Never put credentials in browser code or documentation. Restart the server after changing its credentials.
  4. Select Check connection. Saving settings or checking a connection does not create the index.
  5. Read and check the consent box, then choose Initialize / repair reference index to upload the 41 bundled reference embeddings and labels.
  6. Identify or enroll against the cloud library. Allow time for indexing changes to become searchable.

Incompatible indexes are rejected rather than overwritten. Initialization does not copy your custom local enrollments or upload raw audio. Cloud failures are reported explicitly, with no automatic fallback to local matching.

Azure Spotlight requirements

Spotlight retrieves reference vectors server-side to compute PCA. New indexes make audio_embeddings retrievable. On first projection, an existing compatible index's hidden field is made retrievable using a conditional schema update, requiring index-update permission; documents are not rebuilt or re-uploaded. Clients with query access can then request those vectors.

If the field was created with stored=false, this cannot be enabled on that field. Use a dedicated index with stored vectors; the app will report the limitation rather than rebuild it. Missing vectors or permission errors can disable Spotlight while recognition continues.

Panel and settings

Close the panel with its top-right X and reopen it with Azure AI Search in the toolbar. Closing does not discard unsaved edits, clear consent, switch backend, or interrupt requests. Unsaved configuration edits disable cloud recognition until resolved. Endpoint/index settings are stored on this computer and shared across tabs; credentials remain server-side.

7. Toolbar and appearance

  • LOCAL / CLOUD badge: shows the selected backend, not connection readiness. Check the separate connection status.
  • Match criteria icon: opens the similarity and candidate-gap controls previously shown below the results. Only one of Match criteria and Appearance can be open at a time.
  • Appearance / Apparence: opens palette, font, and background controls. Outside click or Escape closes it; Escape returns focus to the opener.
  • Palette: Amber, Forest, Ocean, or Rose, each in light/dark mode. The default is Ocean with Tahoma font. Fonts use local installations.
  • Background: import PNG, JPEG, or WebP up to 8 MB, 8192 pixels per side, and 20 megapixels. The adjacent remove button restores a plain background.
  • EN / FR: changes application labels without clearing audio or results. This guide is in English.
  • Clear / Effacer: clears audio, playback, visuals, and results, but not speakers, preferences, criteria, Top N, or the chosen microphone. Disabled during recording or requests.
  • Sidebar: drag the divider or use its arrow keys, Home/End; double-click to reset its width. Mobile navigation wraps instead.

Language, theme, font, backend, and sidebar width are saved in browser local storage. Background images stay in this browser's IndexedDB and are not uploaded. Clearing browser site data removes these preferences and images, but does not delete server-side speaker libraries.

8. Privacy and limitations

  • Use only recordings you have permission to process and enroll. Voice embeddings are sensitive biometric data.
  • Embedding computation is local in both modes. Azure identification sends the query embedding; Azure enrollment stores the embedding and name. Raw audio is not sent to Azure.
  • Identification audio is processed in server memory, not saved. Enrollment persists names and embeddings in the selected database.
  • Browser plot responses contain projected coordinates and scores, not raw 192-dimensional vectors. Names and derived visualizations can still be sensitive; handle screenshots carefully.
  • Protect local databases, the Azure index, and backups. A workspace inside OneDrive may sync local files; use a non-synced location when needed.
  • The demo is not liveness detection, authentication, diarization, or verified identity recognition. Replays, synthetic voices, noise, overlapping speakers, and recording conditions can mislead it.
The app is intended for loopback access on your computer. Remote hosting needs additional authentication, HTTPS, and security work; do not simply expose this development server publicly.

9. Troubleshooting

Microphone permission is denied or no device is available
Check browser and OS permissions, connect a microphone, and use Allow / refresh microphones again. WAV upload remains available.
Audio is rejected
Check format, duration, size, and recording level. Record audible speech without clipping; do not submit silence.
A known person is marked unknown
Try a separate, clear recording and confirm enrollment in the selected backend. Review similarity and separation; do not assume relaxing thresholds improves accuracy.
Azure cannot connect
Save endpoint/index edits, check server credentials and assigned roles, then check the connection. A service-bound API key cannot be forwarded to a different endpoint. Consult server logs without sharing credentials.
Azure enrollment is not visible yet
Indexing is eventually consistent. Wait briefly, refresh the connection, and analyze again.
The map is empty or unavailable
Identify audio first. If a map error is displayed, retry it. For Azure, check vector retrieval/storage and index-update permission. Recognition can still succeed independently.
3D does not spin
Select 3D, keep the tab visible and focused, and check the system's reduced-motion preference. Drag to rotate manually.
Preferences or background cannot be saved
Check browser site-storage restrictions. Appearance can still apply during this visit, but may not persist.
Qdrant reports a storage lock
Run only one app process against the data directory. Stop the existing server with Ctrl+C before starting another; do not use multiple workers.

10. Installation and operation

Python 3.11 is recommended. From the supplied project folder in PowerShell:

python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cpu --no-deps torch==2.5.1+cpu torchaudio==2.5.1+cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe prepare_assets.py
.\start.ps1

Dependency installation requires internet access. The local mode needs no Docker, separate Qdrant service, Azure credentials, or frontend build. Model assets are prepared from the supplied files rather than downloaded at runtime.

If PowerShell blocks scripts, start Python directly without changing execution policy:

.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8765

Stop the server with Ctrl+C. Use .\start.ps1 -Port 8766 for a different port. Run only one instance per data directory. Later starts reuse cached reference embeddings.

Local persistence is in data\voices.sqlite3 and data\qdrant; bundled weights and WAVs are in data\model and data\references. Consult the project's README for developer API, persistence, and test details.

11. Export analysis reports

After identification, use Export analysis in the Recognition result panel. Exports are unavailable while recording or processing. They use the applied criteria and server timings from that result, not later edits to Match criteria.

  • Printable HTML: a standalone report with scores, backend, timestamps, criteria, audio duration, warnings, expected test speaker, and a snapshot of the current 2D/3D Spotlight view. Download, open in a browser, and use Ctrl+P to print or save as PDF. Capturing stops automatic spin. If the map is unavailable, the report states this explicitly.
  • CSV: one row per displayed candidate, with repeated analysis metadata and signed numeric cosine scores. A result with no candidates still exports one metadata row. Text that could be interpreted as a spreadsheet formula is prefixed with an apostrophe.
  • JSON: structured data with schema version 1, displayed candidates, decision, applied thresholds, timing, and projection/camera metadata. The image is included only in HTML.

The export records the analyzed Top N, current display limit, and exported row count. Lowering Top N trims exported candidates just as it trims the visible list. Analysis completion and export timestamps are UTC. Timings exclude browser/network time.

Reports contain names, audio labels and derived visualization data. Protect downloaded files. No audio or raw embeddings are exported, and the app does not store report files on the server.

12. Guided demo

Select the play-circle icon in the top bar to start a six-step walkthrough. It is non-modal, so you can keep interacting with the application.

  1. Use Show control to open Test audio; select and explicitly load a held-out clip.
  2. Click Identify speaker in the app. In Azure mode this sends the query embedding to your configured service.
  3. Inspect the decision, signed similarities, gap, and expected speaker.
  4. Select 3D and try rotating, panning, zooming, or optional spin. Skip this step if the map is unavailable.
  5. Optionally export a report before moving on.
  6. Optionally switch backend yourself and identify the same audio again. Azure setup and initialization still require your existing explicit configuration and consent. Compare the exported reports manually; libraries may differ.

Use Back, Next, or Skip step to control progress. The guide never runs analysis, loads audio, switches backends, enrolls voices, or initializes Azure automatically. Close it with X or Escape without cancelling requests or clearing audio/results. Navigating to Speaker library closes it; reopening restarts from step one. Reduced-motion settings continue to apply.
